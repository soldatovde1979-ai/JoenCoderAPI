# OpenCoder для 1С 8.2 — комплект и инструкция

Отправка запросов к шлюзу OpenCoder из 1С 8.2 (8.2.19 и новее) напрямую, без
`gw-proxy`. Модуль не привязан к конфигурации: его текст вставляется в общий
модуль, модуль формы или внешнюю обработку.

```
1С (тело запроса в файл)  →  node oc-sign-cli.mjs  →  заголовки подписи + тело
1С  →  HTTPS POST с заголовками  →  https://code.accelstacks.com/gw/v1/chat/completions
```

## Состав папки

| Файл | Назначение |
|---|---|
| `OpenCoder.bsl` | Модуль для 1С. Вставляется в конфигурацию целиком |
| `oc-sign-cli.mjs` | Подписант: считает заголовки ed25519-v1 и отдаёт их в файл |
| `oc-sign.mjs` | Тонкая ESM-обёртка над `oc-sign.cjs` (рядом, обязательна) |
| `oc-sign.cjs` | Реализация подписи (рядом, обязательна) |

Папку можно переносить: все пути внутри относительные. После переноса
поправьте только `ПутьКПодписанту` (см. «Настройки»).

## Требования

- Платформа 1С **8.2.19+** (`ЗащищенноеСоединениеOpenSSL`, `HTTPЗапрос` с заголовками).
- **Node.js 18+** на машине, где выполняется 1С.
- Файл `%LOCALAPPDATA%\OpenCoder\cc-web-credentials.json` — создаётся после
  входа в OpenCoder. Если он лежит в другом месте или 1С работает под другой
  учётной записью, путь задаётся полем `ПутьККреденшалам`.
- Корневой сертификат шлюза в хранилище «Доверенные корневые центры» Windows.
  Без него `ЗащищенноеСоединениеOpenSSL` завершит запрос ошибкой TLS.
- Право на запуск процессов (`ЗапуститьПриложение`).

**Где работает:** толстый и тонкий клиент, сервер, внешнее соединение.
**Где не работает:** веб-клиент — в нём `ЗапуститьПриложение` недоступно.

На сервере процесс `node` стартует под пользователем службы 1С, у которого
обычно нет профиля OpenCoder. Тогда задайте `ПутьККреденшалам` на доступную
копию файла либо вызывайте функцию с клиента.

## Установка

1. Скопируйте папку `1c` на машину, где будет работать 1С.
2. Откройте `OpenCoder.bsl`, в функции `НастройкиOpenCoder()` проверьте
   `ПутьКПодписанту` — он должен указывать на `oc-sign-cli.mjs` **в этой папке**.
   При необходимости укажите полный путь к `node.exe`.
3. Вставьте текст модуля в общий модуль (для вызова с сервера — флаг
   «Сервер») или в модуль обработки.
4. Проверьте связку из командной строки (см. «Проверка без 1С»).

## Пример 1. Нормализация наименования карточки обращения

Типовая задача: есть сырое наименование (регистр, опечатки, лишние символы,
обрывки) и тело обращения. Нужно получить короткое корректное наименование
карточки.

```bsl
// Сырые данные из карточки
НаименованиеСырое = "не работет прнтер!!! сроч";
ТелоОбращения     = "Здравствуйте! Вчера после обновления 1С перестал печатать
                     |принтер HP LaserJet M404 на складе. Переустановка драйвера
                     |не помогла, в очереди висят 3 задания.";

СистемныйПромпт =
	"Ты нормализуешь наименования карточек обращений в службу поддержки.
	|Верни ТОЛЬКО нормализованное наименование — одну строку, без кавычек,
	|без точки в конце, без пояснений.
	|Правила:
	|— длина 40–90 символов, первое слово с заглавной буквы;
	|— устрани опечатки и лишние знаки, но не выдумывай факты;
	|— используй термины из тела обращения (устройство, система, операция);
	|— не добавляй статус, приоритет и имя заявителя;
	|— если данных не хватает, сформулируй нейтрально по имеющемуся тексту.";

ТекстЗапроса =
	"Наименование (неизвестной степени нормализации): " + НаименованиеСырое + Символы.ПС
	+ "Тело обращения: " + ТелоОбращения;

Результат = ОтправитьЗапросOpenCoder(ТекстЗапроса, "flash", СистемныйПромпт);

Если Результат.Успех Тогда
	НаименованиеНормализованное = СокрЛП(Результат.ТекстОтвета);
	// Фактический ответ на этом примере:
	// "Принтер HP LaserJet M404 не печатает после обновления 1С на складе"
Иначе
	Сообщить("OpenCoder: " + Результат.Ошибка);
КонецЕсли;
```

Тот же запрос с температурой ниже нуля для более предсказуемого результата:

```bsl
Результат = ОтправитьЗапросOpenCoder(ТекстЗапроса, "flash", СистемныйПромпт, 0.2);
```

## Пример 2. Простой вопрос

```bsl
Результат = ОтправитьЗапросOpenCoder("Сколько будет 2+2? Ответь одним словом.");
Если Результат.Успех Тогда
	Сообщить(Результат.ТекстОтвета);   // "Четыре"
Иначе
	Сообщить("Ошибка: " + Результат.Ошибка);
КонецЕсли;
```

## Пример 3. Классификация обращения

```bsl
СистемныйПромпт =
	"Ты классифицируешь обращения службы поддержки.
	|Верни строго одно слово из списка: Оборудование, Программы, Доступы, Другое.
	|Никаких пояснений и знаков препинания.";

Результат = ОтправитьЗапросOpenCoder(
	"Обращение: " + ТелоОбращения,
	"flash",
	СистемныйПромпт,
	0);

Если Результат.Успех Тогда
	Категория = СокрЛП(Результат.ТекстОтвета);
КонецЕсли;
```

## Пример 4. Свой JSON: несколько сообщений, `response_format`

Функция `ОтправитьЗапросOpenCoderJSON()` принимает готовое тело запроса —
пригодится, когда нужны поля, которых нет в простой функции.

```bsl
ТелоЗапроса =
	"{""model"":""flash"",""stream"":false,"
	+ """temperature"":0,"
	+ """messages"":["
	+   "{""role"":""system"",""content"":""Отвечай только JSON без пояснений.""},"
	+   "{""role"":""user"",""content"":""Извлеки из текста устройство и город. "
	+     "Текст: Принтер в офисе Казань не печатает. "
	+     "Формат: {\""device\"":\"\",\""city\"":\"\"}""
	+ "]}";

Результат = ОтправитьЗапросOpenCoderJSON(ТелоЗапроса);
Если Результат.Успех Тогда
	Сообщить(Результат.ТекстОтвета);   // {"device":"Принтер","city":"Казань"}
КонецЕсли;
```

## Настройки

Все настройки — в функции `НастройкиOpenCoder()`. Можно не править её, а
передать свою структуру последним параметром:

```bsl
Настройки = НастройкиOpenCoder();
Настройки.Модель = "pro";
Настройки.Таймаут = 300;
Результат = ОтправитьЗапросOpenCoder("Сложный вопрос", "", "", Неопределено, Настройки);
```

| Поле | По умолчанию | Что задаёт |
|---|---|---|
| `Сервер` | `code.accelstacks.com` | Хост шлюза |
| `Порт` | `443` | Порт HTTPS |
| `ПутьЗапроса` | `/gw/v1/chat/completions` | Путь HTTP-запроса |
| `АдресПодписи` | `https://code.accelstacks.com/gw/v1/chat/completions` | URL, который подписывается. Должен совпадать с фактическим запросом |
| `ПутьКNode` | `node` | `node.exe`; укажите полный путь, если Node не в `PATH` |
| `ПутьКПодписанту` | `...\1c\oc-sign-cli.mjs` | Файл подписанта в этой папке |
| `ПутьККреденшалам` | пусто | Пусто — `%LOCALAPPDATA%\OpenCoder\cc-web-credentials.json` |
| `КаталогОбмена` | пусто | Пусто — временный каталог. Задайте ASCII-путь без пробелов, если запуск `node` не срабатывает |
| `Модель` | `flash` | Модель по умолчанию (`flash`, `pro`) |
| `Таймаут` | `180` | Секунды ожидания ответа |

## Результат

Любая функция возвращает структуру:

| Поле | Тип | Содержимое |
|---|---|---|
| `Успех` | Булево | `Истина` при HTTP 200 |
| `КодСостояния` | Число | HTTP-код (`0` — запрос не дошёл до шлюза) |
| `ТекстОтвета` | Строка | `choices[0].message.content` |
| `ТелоОтвета` | Строка | Тело ответа целиком (JSON) |
| `Ошибка` | Строка | Причина отказа, пусто при успехе |

## Проверка без 1С

Подпись считается отдельно от 1С, поэтому связку можно проверить в консоли:

```bat
cd /d C:\Projects\OpenCoderAPI\ZOO\1c
echo method	POST>in.txt
echo url	https://code.accelstacks.com/gw/v1/models>>in.txt
node oc-sign-cli.mjs in.txt out.txt
type out.txt
```

Ожидается 7 строк `header<TAB>имя<TAB>значение` и строка `bodyfile<TAB>...`.
Если вместо них `error<TAB>...` — причина написана там же.

## Диагностика

| Сообщение | Причина и что делать |
|---|---|
| `Не найден подписант OpenCoder: ...` | Неверный `ПутьКПодписанту` или папку перенесли |
| `Не удалось запустить подписант (...)` | `node` не в `PATH` / нет прав на запуск процессов. Укажите полный путь в `ПутьКNode` |
| `Подписант: нет ключа подписи в ...` | Не выполнен вход в OpenCoder или не тот `ПутьККреденшалам` |
| `Подписант не создал файл заголовков ...` | `oc-sign.cjs` и `oc-sign.mjs` не лежат рядом с `oc-sign-cli.mjs` |
| `HTTP-запрос ... не выполнен: ... TLS` | Сертификат шлюза не в «Доверенных корневых центрах» Windows |
| `Шлюз вернул HTTP 401: ...` | Токен OpenCoder просрочен — войдите в OpenCoder и повторите |
| `Шлюз вернул HTTP 502/503: ...` | Проблема на стороне шлюза; текст ошибки — в сообщении |
| `ТекстОтвета` пустой при `Успех = Истина` | Модель вернула `content: null` (только `tool_calls`); полный ответ — в `ТелоОтвета` |

## Ограничения

- Подпись ed25519 считается в Node: во встроенном языке 8.2 нет битовых
  операций и 64-битной арифметики с переносом.
- Разбор ответа упрощённый: ищется `choices` → `message` → `content`.
  Полный JSON всегда доступен в `ТелоОтвета`.
- Каждый вызов пишет 3–4 временных файла в каталог обмена и удаляет их после
  ответа. При аварийном завершении процесса файлы остаются — каталог можно
  чистить по маске `oc_*`.
- Запросы не стриминговые (`stream: false`): ответ приходит целиком.
